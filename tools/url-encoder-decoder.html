What Is the URL Encoder / Decoder?

URLs can only contain a limited set of characters. Spaces, ampersands, question marks, hash signs and non-Latin letters all have special meanings or are simply not allowed, so they must be encoded before they can travel inside a URL. This URL Encoder and Decoder applies the standard percent-encoding rules instantly, in both directions.

Encoding turns unsafe characters into percent signs followed by hexadecimal codes: a space becomes 20 percent, an ampersand becomes 26 percent. Decoding reverses the process. The tool offers both the full component mode, which escapes every reserved character, and a lighter mode that preserves URL structure.

Developers use it when building query strings and debugging request URLs; marketers use it to decode the tracked links they receive; analysts use it to read the encoded parameters inside analytics URLs. It runs entirely in your browser, so nothing you paste is transmitted anywhere.

How to Use the URL Encoder / Decoder

Paste your text or URL, choose the encoding mode that matches your task, and the converted result appears instantly. Decode works the same way in reverse, turning percent-encoded strings back into readable text.

  1. Paste the text or URL you want to convert.
  2. Choose encode or decode.
  3. Pick the mode: full component encoding, or preserve-structure encoding for complete URLs.
  4. Review the converted output.
  5. Copy the result for use in your link, request or document.

How the URL Encoder / Decoder Works

Percent-encoding replaces each unsafe character with a percent sign and its two-digit hexadecimal byte value in UTF-8. A space becomes 20 percent, a slash becomes 2F percent, and characters outside ASCII, such as accented letters or CJK text, become one escape sequence per UTF-8 byte, which is why they grow noticeably when encoded.

The two modes exist because URLs have structure. Component mode escapes everything, including ampersands, equals signs and question marks, which is what you want for a value being placed inside a query parameter: an ampersand inside a value must be escaped or it will be mistaken for a parameter separator. Preserve-structure mode leaves the URL's own punctuation alone and encodes only the characters that are genuinely unsafe.

Decoding reverses the mapping, converting each percent escape back to its character using UTF-8. A common debugging insight comes from decoding analytics and campaign URLs, where parameters like source, medium and campaign are visible only after decoding. If decoding produces mangled text, the string was probably double-encoded, and decoding it twice restores it.

The reserved characters are worth knowing by name because each one breaking a URL is a debugging story waiting to happen. The question mark separates the path from the query. The ampersand separates parameters. The equals sign joins a parameter to its value. The hash starts a fragment that never reaches the server. Each of these inside a parameter value must be encoded, or the URL's structure changes in exactly the way its author did not intend.

Internationalised URLs add a second layer: the address bar shows readable Unicode, while what travels on the wire is percent-encoded UTF-8. This is why copying a URL with non-Latin text sometimes produces an unreadable string of escapes, and why decoding is the reliable way to see what a link actually contains. Both views are correct; they are just layers of the same system.

Examples and Practical Use Cases

Building a query string

A search term containing spaces and an ampersand, fish and chips, must be encoded before being placed into a query parameter. Component mode produces fish20percent26and20chips-equivalent output, keeping the value intact through the request.

Decoding a tracked link

A marketing URL arrives crowded with percent escapes. Decoding it reveals readable parameters such as utm_source equals newsletter and utm_campaign equals spring_sale, making the tracking legible.

Debugging a broken request

An API call fails because an unencoded hash in a parameter truncates the URL at the server. Encoding the parameter value fixes the request, and the tool shows exactly what the encoded form should be.

Common Mistakes to Avoid

  • Building query strings by string concatenation without encoding values, then debugging why ampersands split parameters.
  • Encoding an entire URL including its structure, when only a parameter value needed encoding.
  • Assuming a plus sign means a space in every context; that convention applies to form data, not paths.
  • Double-encoding by running encoded text through another encoder.

Tips, Benefits and Limitations

  • Use component mode for values placed inside query parameters; it prevents separator confusion.
  • Use preserve-structure mode for whole URLs you want to keep navigable.
  • Double-encoded text decodes to percent-escaped output; decode twice to fully restore it.
  • Spaces in URLs are technically invalid; always encode them as 20 percent.
  • Non-Latin text grows several times when encoded because each UTF-8 byte becomes its own escape.

Frequently Asked Questions

What is the difference between encoding a component and a full URL?

Component encoding escapes every reserved character, including ampersands and equals signs, which is correct for parameter values. Full-URL encoding preserves the URL's structural punctuation.

Why do spaces sometimes appear as plus signs?

Plus-for-space is a convention from form encoding, not standard percent-encoding. This tool uses proper 20 percent escapes, which are universally accepted.

Why is my encoded text so much longer?

Each unsafe byte becomes three characters, and non-ASCII characters use multiple UTF-8 bytes. Growth of several times is normal for non-Latin text.

Can I decode a fragment of a URL?

Yes. Paste any encoded fragment. Decoding works on any string, not only complete URLs.

Is encoding the same as encryption?

No. Encoding is a reversible, public transformation with no secret. It changes how data looks, not who can read it.

Is my data uploaded?

No. All encoding and decoding happens locally in your browser.

Why does my decoded text still look encoded?

It was probably encoded twice, which happens when a framework encodes automatically and the value was encoded manually first. Decode again to fully restore it.

Should path segments be encoded?

Yes, each segment individually, using component-style encoding. Characters like spaces and slashes inside a segment must be escaped, while the segment separators themselves stay literal.

Do I need to encode the hash fragment of a URL?

Only if the fragment's content contains reserved characters. The fragment never reaches the server, but the browser still parses it, so encoding its values keeps the URL unambiguous.
