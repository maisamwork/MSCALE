Regex Tester

Test regular expressions online with live match highlighting and capture groups.

What Is the Regex Tester?

Regular expressions are the sharpest tool in text processing and the easiest to get subtly wrong. A pattern that works on your test string fails on real data; a greedy match swallows too much; a group captures the wrong slice. This Regex Tester shows exactly what your pattern matches, live, with highlighting that makes every match visible.

Enter a pattern and a test string, and the tool lists every match with its position, highlighting them inside the original text. Flags such as case-insensitive, global and multiline are a click away, and capture groups are broken out so you can see precisely what each parenthesis captured.

Developers use it while writing validation and parsing logic, data workers use it to build extraction patterns, and learners use it to understand how patterns behave. Seeing matches update as you type shortens the write-test-fix loop from minutes to seconds, which is how regex skills actually develop.

How to Use the Regex Tester

Type a pattern, paste a test string, and read the results: highlighted matches in the text plus a list of each match with its position and captured groups. Adjust flags to change how the pattern is interpreted, and refine until the matches are exactly what you need.

  1. Type or paste your regular expression into the pattern box.
  2. Paste your sample text into the test area.
  3. Watch the matches highlight and the match list update live.
  4. Toggle flags such as case-insensitive, global and multiline as needed.
  5. Inspect capture groups for each match, then refine the pattern until it is exact.

How the Regex Tester Works

The tool compiles your pattern with the browser's regular expression engine, the same syntax used in JavaScript and closely aligned with other mainstream flavours. Each match is reported with its index in the text, its full text, and the contents of any capture groups, numbered in order of their opening parentheses.

Flags change interpretation in important ways. Without the global flag the engine stops at the first match, which is useful for testing whether a pattern matches at all. Case-insensitive mode makes letter comparisons ignore case. Multiline mode makes the caret and dollar anchors apply at every line break rather than only at the string's ends.

Two classic behaviours become visible here. Greedy quantifiers consume as much as possible, so a dot-star pattern often spans further than intended; the highlight shows this immediately. And special characters such as dots and brackets carry meaning, so a literal dot must be escaped with a backslash. Watching the highlight while toggling these details builds correct intuition faster than any reference page.

A short tour of the constructs that do most of the work in real patterns: alternation with the pipe character chooses between options, so cat|dog matches either. Character classes with ranges, like a-z or 0-9, match one character from a set, and negation with a leading caret matches anything outside the set. Quantifiers apply to the preceding element, and grouping with parentheses both binds quantifiers to sequences and captures text for later use.

Lookahead and lookbehind, the zero-width constructs, are the step from competent to powerful: they assert what must surround a match without consuming it, enabling patterns like match every word not followed by a comma. The tester is the ideal place to learn them because the highlight shows exactly what is and is not consumed, which is the property that makes these constructs confusing in prose and obvious in practice.

Examples and Practical Use Cases

Building an email validation pattern

Start with a simple pattern, paste a list of valid and invalid addresses, and refine until the highlights divide them correctly. The live feedback shows precisely which edge cases the pattern still accepts.

Extracting data from logs

A pattern with capture groups pulls timestamps and error codes out of log lines. The group breakdown confirms each group captures the intended slice before the pattern goes into production code.

Learning anchors and boundaries

A learner tests the difference between matching cat anywhere and matching it only at word boundaries. The highlight shows category matching in one case and not the other, making the concept concrete.

Common Mistakes to Avoid

  • Writing greedy patterns that swallow more than intended and not noticing until real data breaks them.
  • Forgetting the global flag and concluding a pattern matches only once.
  • Escaping incorrectly, double-escaping characters that needed one backslash.
  • Testing only on clean sample data that lacks the messy real-world cases.

Tips, Benefits and Limitations

  • Include intentionally tricky cases in your test string: empty lines, duplicates, edge values.
  • Use the global flag to see all matches; without it you only see the first.
  • Escape literal dots, brackets and other special characters, or they will act as operators.
  • Name your capture groups in complex patterns to keep the group list readable.
  • Test the negative case too: strings your pattern should not match are as important as those it should.

Frequently Asked Questions

Which regex flavour does the tool use?

The browser's JavaScript engine, which follows the ECMAScript flavour. It is very close to PCRE for common patterns, with minor differences in advanced constructs.

What do the flags mean?

Global finds all matches rather than stopping at the first. Case-insensitive ignores letter case. Multiline makes anchors apply at line breaks. Dotall lets the dot match newlines.

Why does my pattern match too much?

Greedy quantifiers consume as much as possible. Make them lazy with a question mark after the quantifier, or narrow the character class to stop earlier.

How do I match a literal dot or bracket?

Escape it with a backslash. Unescaped, these characters are operators with special meaning.

Can the tool replace text too?

This tool focuses on testing and visualising matches. For replacements, use the Find and Replace tool, which supports regex with capture-group references.

Is my pattern or text uploaded?

No. All matching happens locally in your browser.

Why do my results differ from another language's regex?

Flavours differ in advanced constructs. The core syntax is shared, but features like lookbehind and Unicode handling vary; test in the flavour your code will use.

How do I match a whole word?

Wrap the term in word-boundary anchors, the backslash-b sequence, so cat matches in the cat sat but not in category.
